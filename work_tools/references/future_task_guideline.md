# 가이드라인: 추후 작업 (TODO)

## 개요
당장 급하지는 않지만 팀 내부적으로 개선이 필요하거나 나중에 수행해야 할 작업들을 **User Story** 단위로 등록합니다. 팀 내 백로그 개념으로 관리하며, 구체적인 세부 작업이 있을 경우 하위 Task로 분리합니다.

## 제목 패턴
- `[TODO] {개선/작업_내용}`
- 예: `[TODO] 정적 자원 캐싱 정책 최적화`

## 📌 커스텀 필드 (Custom Fields) 가이드
- **기능 상세 (ID: 8)**: 적용해야 할 개선 사항의 기대 효과 및 목적 기입
- **개발 완료 예정일 (ID: 9)**: 백로그에서 실제 스프린트로 편입되어 일정이 잡힐 때 기입 (생성 시점에는 비워둠)

## 설명 템플릿 (Description)
```markdown
### 작업 배경
- 현재: {현재 상태 설명}

### 주요 작업 내용
- [ ] {작업_항목_1}
- [ ] {작업_항목_2}

### 예상 시점
- 특정 마일스톤 또는 여유 시간 발생 시 검토
```
