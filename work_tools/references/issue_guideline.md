# 가이드라인: 고객사 이슈 등록

## 개요
고객사로부터 접수된 이슈 내용을 바탕으로 Taiga **User Story**를 생성할 때 사용합니다. 복사된 이슈 내용을 분석하여 핵심 문제를 식별하고 해결을 위한 체크리스트를 도출합니다.

## 제목 패턴
- `{고객사명}: {이슈_핵심_내용}`
- 예: `A사: 로그인 시 401 에러 반복 발생 건`

## 📌 커스텀 필드 (Custom Fields) 가이드
- **동작 시나리오**: 버그 재현 경로 및 테스트/검증 시나리오 기입
- **개발 완료 예정일**: 고객사 피드백을 위한 1차 수정 완료 목표일 기입. 특정일자 요청 확인 가능한 경우에만 기입

## 설명 템플릿 (Description)
```markdown
### 이슈 현상
{이슈 원문 내용 요약}

### 원인 분석 (예상)
- 관련 로그 확인 (Server/Client)
- 재현 경로 테스트
- 특정 계정/환경 문제 여부 확인

### 대응 계획
- 원인 파악 및 버그 수정
- 수정 사항 검증 (QA)
- 고객사 피드백 및 배포 안내

### 관련 자료
- 기술지원(IMS): {링크}
```
