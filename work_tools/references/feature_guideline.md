# 가이드라인: 특정 기능 추가 (Feature)

## 개요
팀 내부에서 도출된 신규 기능이나 대규모 변경 사항을 **User Story** 단위로 등록합니다. User Story는 큰 단위로 유지하되, 하위 Task는 실행 가능한 단위로 상세히 쪼개는 것을 목표로 합니다.

## 제목 패턴
- `{기능명}: {핵심_구현_내용}`
- 예: `알림 센터: 실시간 푸시 알림 연동 및 이력 조회`

## 📌 커스텀 필드 (Custom Fields) 가이드
본문에 길게 적는 대신, 커스텀 필드 항목을 적극 활용해 주세요.
- **기능 상세**: 해당 기능의 목적 및 핵심 로직 요약. 한~두 문장으로 간결하게 작성.
- **동작 시나리오**: QA에서 확인할 수 있는 유저 스토리 기반의 동작 시나리오 상세

## 설명 템플릿 (Description)
```markdown
### 상세 설계 및 체크리스트
- **백엔드**
  - [ ] API 엔드포인트 설계 및 구현
  - [ ] DB 스키마 변경 (필요 시)
- **프론트엔드**
  - [ ] UI 컴포넌트 개발
  - [ ] API 연동 및 상태 관리
- **공통**
  - [ ] 단위 테스트 작성 및 통합 테스트

### 관련 자료
- 기획서: {링크}
- 디자인: {Figma 링크}
```
